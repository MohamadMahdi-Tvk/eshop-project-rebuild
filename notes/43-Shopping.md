# Shopping

ما برای سبد خرید خود، دو تا مدل نیاز داریم؛ مدل اول سبد خرید هست که مشخص میکند این سبد خرید برای چه کسی هست، آیا این سبد
خرید فاکتورش نهایی شده است و کاربر آن را پرداخت کرده است یا نه؛ کلاس مدل بعدی، محصولی هست که داخل سبد خرید قرار داده شده
است، که شامل خود محصول، تعداد محصول، قیمت نهایی محصول و... میباشد. ما می توانیم یک اپ جدید به اسم اوردرماژول برای این
کار در نظر بگیریم.

## Order:

ما یک سبد خرید داریم که همان کلاس مدل اوردر است، که یکسری مشخصات دارد، یعنی در سایت باید مشخص شود این سبد خرید برای چه
کسی است، پس با کلاس یوزر در ارتباط است که مشخص شود این سبد خریدی که الان باز هست برای کدام کاربر است و محصولی که داره
ادد میشه برای چه کاربری اضافه میشود؛ دو فیلد ایزپید و پیمنت دیت، برای بعد از فرآیند خرید و پرداخت است، یعنی پرداخت اگر
انجام شده در چه تاریخی پرداخت صورت گرفته است:

```
class Order(models.Model):
    user = models.ForeignKey(User, on_delete=models.CASCADE, verbose_name='کاربر')
    is_paid = models.BooleanField(verbose_name='نهایی شده / نشده')
    payment_date = models.DateField(null=True, blank=True, verbose_name='تاریخ پرداخت')

    def __str__(self):
        return str(self.user)

    class Meta:
        verbose_name = 'سبد خرید'
        verbose_name_plural = 'سبد های خرید کاربران'
```

## OrderDetail:

ما نمیتوانیم از خود محصول به عنوان محصولات سبد خرید استفاده کنیم، یعنی نمیتونیم بریم داخل مدل اصلی پروداکت و رابطه با
اوردر ایجاد کنیم؛ فرضا یک گوشی موبایلی را میخواهیم خریداری کنیم الان قیمت فعلی آن ده میلیون است و وقتی پرداخت رو انجام
میدیم برای ما ده میلیون درنظر گرفته میشود؛ اما یکهو میبینیم فردا، هفته ی بعد یا ماه بعد، میبینیم که قیمت آن عوض شده است؛
اگر از خود پروداکت استفاده کرده باشیم، فاکتور های قبلی هم تحت تاثیر قرار میگیرند واون قیمتی هم که ما پرداخت کرده ایم هم
عوض میشود، یعنی توی سیستم عوض میشود و برای ما تغییری ایجاد نمیکند؛ پس ما برای اینکه این تغییر ایجاد نشود، یک جدول
اوردردیتیل درنظر میگیریم که با مدل اوردر در ارتباط است؛ یعنی ما سبد خریدی داریم و میخواهیم یک محصولی را برای این سبد
خرید درنظر بگیریم، اون سبد خرید برای ماست، این محصولی هم که اضافه میشود در قالب یک اوردردیتیل به آن اوردر اضافه میشود که
مشخص شود این محصول برای کدام سبد خرید و برای چه کسی داره اضافه میشود؛ اون دیتیلی هم که داره اضافه میشود باید مشخص کنیم
شامل چه محصولی است، پس با مدل پروداکت باید رابطه داشته باشد؛ مورد بعدی اینکه ممکنه تفاوت قیمت باعث ایجاد دردسر شود؛ تا
قبل از پرداخت مشکلی ایجاد نمیکند، یعنی ما عملا از قیمت خود محصول در مدل خود پروداکت که ذخیره شده استفاده میکنیم، اما بعد
از پرداخت دیگه این کار را انجام نمی دهیم و از فاینال پرایس استفاده میکنیم، چون اگر قیمت عوض شود، نباید تغییری در فاکتور
ما ایجاد شود؛ فیلد بعدی تعداد محصول است، چون از یک محصول ممکن هست چند تا بخواهیم خرید کنیم:

```
class OrderDetail(models.Model):
    order = models.ForeignKey(Order, on_delete=models.CASCADE, verbose_name='سبد خرید')
    product = models.ForeignKey(Product, on_delete=models.CASCADE, verbose_name='محصول')
    final_price = models.IntegerField(null=True, blank=True, verbose_name='قیمت نهایی تکی محصول')
    count = models.IntegerField(verbose_name='تعداد')

    def __str__(self):
        return str(self.order)

    class Meta:
        verbose_name = 'جزئیات سبد خرید'
        verbose_name_plural = 'لیست جزئیات سبد های خرید'
```

### note:

زمانی که کاربر روی دکمه افزودن سبد خرید کلیک میکند، اول باید چک کنیم آیا این کاربر لاگین هست یا خیر، اگر لاگین نبود،
باید بره صفحه لاگین و لاگین کند، و اگر هم لاگین بود، و روی افزودن به سبد خرید کلیک کرد، میریم چک میکنیم آیا سبد خرید
بازی از قبل دارد یا خیر، که همان ایزپید در مدل اوردر هست، یعنی اگر ایزپید ترو باشد یعنی سبد خرید پرداختش انجام شده است و
سبد خرید بازی وجود ندارد؛ در حالت کلی هم یک کاربر زمانی که وارد سایت میشود، باید یک سبد خرید باز برایش درنظر بگیریم؛
یعنی زمانی که یک محصولی به سبد خرید خودش اضافه میکند، چک میکنیم اگر سبد خرید بازی نداشت، اول آن سبد خرید را برایش
میسازیم و بعد محصول را به سبد خرید او اضافه میکنیم و در قسمت سبد خرید سایت هم میتواند محصولاتش را مشاهده کند.
