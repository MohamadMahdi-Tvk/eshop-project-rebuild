# Permission

اگر در پنل ادمین، یک کاربری رو باز کنیم، یکسری گزینه هایی را مشاهده میکنیم، در اینجا یکسری گروه داریم، یکسری اجازه یا
پرمیشن داریم، و یک گزینه سوپر یوزر، یا ابرکاربر هم داریم، این سه آیتم در بحث پرمیشن، یکجورایی همه چیز را کنترل میکنند،
فیلد وضعیت کارمندی برای این هست که مشخص کند یک کابر اجازه ورود به صفحه ی جنگو را دارد یا خیر؛ و بحث پرمیشن خاصی را اعمال
نمی کند. ایز استف در جدول برای بررسی کارمند بودن هست و ایزسپوریوزر برای سوپریوزر هست. بصورت کلی سیستم دسترسی در جنگو به
این صورت هست که به ازای هر مدلی که ما در پروژه داریم، که این مورد رو از جدول کانتنت تایپ متوجه میشود؛ به ازای هر کدام،
جنگو در جدول پرمیشن هایی که در نظر گرفته است، 4 تا دسترسی برای عملیات کراد اعمال میکند؛ ما میتوانیم این پرمیشن ها را
بصورت تکی یا دستی، مستقیما به خود شخص بدهیم؛ یعنی در همان لیست اجازه های کاربری موجود، انتخاب کرده و آنها را با فلش هایی
که قرار داده ببریم در لیست کناری، یعنی لیست اجازه های کاربر انتخاب شده؛ و اینجوری برای هر کاربر میتونیم دسترسی هایی را
مشخص کنیم؛ اما بعضی مواقع پیش میاد که اگر بخواهیم به ازای هر کاربر، یکسری پرمیشن اضافه کنیم، کار وقت گیری خواهد بود. به
همین دلیل باید از گروه استفاده کنیم.

## Group

با استفاده از گروه، میتوان گروهی از پرمیشن ها را ایجاد کرد، و به آن گروه مجموعه ای از پرمیشن هایی که میخواهیم رو پاس
میدیم آن گروه ها را به کاربران متصل میکنیم، این باعث میشود ما ساده تر بتوانیم مجموعه ای پرمیشن ها را به مجموعه از
کاربران همزمان متصل کنیم. پس ابتدا میریم یک گروه جدید از طریق پنل ادمین اضافه میکنیم، از لیست اجازه های موجود، هرکدام را
خواستیم به جدول اجازه های انتخاب شده میبریم، و ذخیره میکنیم، حالا که یک گروه جدید ساختیم، میتوانیم به هر کاربری که
خواستیم، آن گروه را بدهیم.

## Superuser

اگر تیک آن خورده باشد، آن کاربر به همه چیز دسترسی خواهد داشت. اگر تیک آن خورده باشد، دیگه سامانه گروه ها و اجازه ها را
بررسی نمی کند. و مستقیم دسترسی همه چیز را به آن کاربر می دهد.

## permission_required

در پارامتر ورودی، یک یا مجموعه ای از پرمیشن هایی که مورد نیاز هست رو دریافت میکند، ورودی لاگین_یوآرال، برای ریدایرکت
کردن کاربر به یک صفحه ی خاص استفاده میشود که این صفحه میتواند صفحه لاگین نباشد و یک صفحه پرمیشن دینایدی باشد که خودمان
طراحی کرده ایم، ورودی بعدی، ریزاکسپشن هست که اگر کاربر دسترسی نداشت، ریدایرکت نکن و خطا برگردان یعنی کاربر استاتوس 403
دریافت میکند، یعنی او به آن صفحه دسترسی ندارد.

1. در ویویی که میخواهیم از چک کردن پرمیشن استفاده کنیم، میتوانیم دو ماژول زیر را ایمپورت کنیم:

```
from django.contrib.auth.decorators import permission_required
from django.contrib.auth.mixins import PermissionRequiredMixin
```

2. ما داخل ورودی پرمیشن_ریکوایرد، میتونیم از داخل جدول آث_پرمیشن و از ستون کدنیم، انتخاب کنیم، اما این کافی نیست، ما
   باید موقع پاس دادن پرمیشن، باید اول مشخص کنیم که این پرمیشن مربوط به کدام یکی از اپ های جنگو هست و بعد از کدنیم
   استفاده کنیم؛ مثلا در این مثلا، اسم اپ آرتیکل ماژول را قرار میدهیم، سپس . و بعدش کدنیم آن پرمیشنی که میخوایم رو قرار
   می دهیم:

```
@permission_required('article_module.view_article', raise_exception=True)
def index(request: HttpRequest):
    return render(request, 'admin_panel/home/index.html')
```

### PermissionRequiredMixin

برای پرمیشن ها در کلاس بیس ویو ها، باید از این میکسین استفاده کنیم، و باید در ورودی اول کلاس پرمیشن ریکوایرددمیکسین رو
قرار بدهیم:

```
class ArticlesListView(PermissionRequiredMixin, ListView):
    model = Article
    paginate_by = 12
    template_name = 'admin_panel/articles/articles_list.html'
    permission_required = ['article_module.view_article']

    def get_context_data(self, *args, **kwargs):
        context = super(ArticlesListView, self).get_context_data(*args, **kwargs)
        return context

    def get_queryset(self):
        query = super(ArticlesListView, self).get_queryset()
        category_name = self.kwargs.get('category')
        if category_name is not None:
            query = query.filter(selected_categories__url_title__iexact=category_name)
        return query
```

یا برای دسترسی به ویرایش مقاله هم میتونیم به این صورت قرار بدهیم و تنظیمات بیشتری برای پرمیشن مشخص کنیم:

```
class ArticleEditView(PermissionRequiredMixin, UpdateView):
    model = Article
    template_name = 'admin_panel/articles/edit_article.html'
    fields = '__all__'
    success_url = reverse_lazy('admin_articles')
    permission_required = ['article_module.change_article']
    raise_exception = True
    permission_denied_message = 'شما دسترسی به این صفحه ندارد!'
```

## Add Custom Permission

ما این امکان را داریم که پرمیشن های خودمان را اضافه کنیم، به یکی از کلاس های مدل خود رفته و در کلاس متای آن میتوانیم یک
لیستی از توپل هاپ برای پرمیشنز درنظر بگیریم؛ مثلا در اپ سایت ماژول، به مدلز می رویم، ورودی اول کدنیم هست، و ورودی دوم
عنوانی هست که برای پرمیشن درنظر میگیریم؛ پس در کلاس متای کلاس مدل سایت ستینگز:

```
class Meta:
   verbose_name = 'تنظیمات سایت'
   verbose_name_plural = 'تنظیمات'
   permissions = [
      (
         "view_adminpanel",
         "دیدن ادمین سایت"
      ),
   ]
```

بعدش حتما باید عملیات مایگریشن را اعمال کنیم؛ و الان اگر به پنل ادمین برویم، این پرمیشن برای ماژول تنظیمات سایت اضافه
شده است، و از آن میتوان در کلاس بیس ویو ها یا فانکشن بیس ویو ها به همان روش هایی که گفتیم استفاده کنیم:

```
@permission_required('site_module.view_adminpanel', raise_exception=True)
def index(request: HttpRequest):
    return render(request, 'admin_panel/home/index.html')
```

و الان که به پنل ادمین بریم، این اجازه را به هر کاربری که خواسته باشیم میتوانیم بدهیم.
