# Change Error Handling

جنگو برای مدیریت یکسری از خطاها، هندلر هایی را تعریف کرده که حالت خاصی از پیاده سازی را دارند و ما میتوانیم آن ها را
اوراید کنیم. اگر وارد فولدر جنگو داخل ونو و سپس کانف و سپس یوآرالز و سپس اینیت آن شویم، 4 تا هندلر را مشاهده میکنیم:

1. `handler400 = defaults.bad_request` :

مثلا وقتی کاربری میخواهد یک فرمی را ثبت کند و اطلاعاتی برای سرور ما میخواهد ارسال کند، ولی این اطلاعات مورد قبول سرور
نیست و اصلاحا بدرکوئست بهش میگیم.

2. `handler403 = defaults.permission_denied` :

وقتی کاربری دسترسی به صفحه یا المانی ندارد.

3. `handler404 = defaults.page_not_found` :

در نتیجه پیدا نشدن یک نتیجه، این ارور برگردانده میشود.

4. `handler500 = defaults.server_error` :

برمیگرده به کد های سرور، یعنی مثلا دیتابیس از کار افتاده، و هر خطای دیگری که مربوط به کدنویسی ما هست.

## Create Custom HTML File For Error

1. داخل فولدر تمپلیتز که در روت پروژه قرار دارد، یک فایل اچتی ام ال دقیقا با کد خطای مد نظر میسازیم:

`403.html`

2. در این صفحه میتوانیم صفحه دلخواه خود را طراحی کنیم:

```
{% extends 'shared/_layout.html' %}

{% block title %}
    عدم دسترسی
{% endblock %}

{% block content %}
    <div class="container">
        <div class="col-lg-12">
            <h1>عدم دسترسی</h1>
            <p>{{ exception }}</p>
        </div>
    </div>
{% endblock %}
```

3. حالا اگر کاربری به صفحه ای وارد شود که دسترسی نداشته باشد، با صفحه ای که ما ساخته ایم مواجه میشود، ما در تگ پی، کلمه
   اکسپشن قرار دادیم، این کلمه از مقدار پرمیشن دینایندمسیج میاد که در کلاس بیس ویو مربوط به ویرایش تعریف کرده بودیم:

`permission_denied_message = 'شما دسترسی به این صفحه ندارید!'`

## Override Error Handler Function

در مرحله قبل ما به ساده ترین روش ممکن صفحه ی خطا را شخصی سازی کردیم؛ اما ما می توانیم هندلر ها را هم اوراید کنیم، یعنی
بیایم یک فانکشنی را تعریف کنیم، هم نام فانکشنی که هندلر دارد و به عنوان هندلر آن را معرفی کنیم. به فایل یوآرالز اصلی
پروژه رفته و این مورد را برای خطای 403 آنجا پیاده سازی می کنیم، اینجوری میتونیم در کانتکس هر دیتایی را هم به صفحه ارسال
کنیم و دستمان خیلی باز تر از روش قبلی است؛ ما میتوانیم فانکشن رو در یک فایل دیگری تعریف کنیم، ولی هندلر باید حتما در
فایل یوآرالز اصلی تعریف شود:

```
def handle_permission_denied(request, exception, *args, **kwargs):
    from django.shortcuts import render

    return render(request, '403.html', {"exception": exception, "data": "This is data"})

handler403 = handle_permission_denied
```

الان اگر اجرا بگیریم و وارد صفحه ای شویم که دسترسی نداشته باشیم، باز هم همان صفحه ای که طراحی کرده بودیم را نمایش میدهد.
و دیتای اضافی که درنظر گرفته ایم و به کانتکس داده ایم هم در صفحه قابل دسترس هست:

```
{% extends 'shared/_layout.html' %}

{% block title %}
    عدم دسترسی
{% endblock %}

{% block content %}
    <div class="container">
        <div class="col-lg-12">
            <h1>عدم دسترسی</h1>
            <p>{{ exception }}</p>
            <p>{{ data }}</p>
        </div>
    </div>
{% endblock %}
```

همین کار را برای باقی خطا ها هم میتوانیم به همین روش انجام دهیم. اما با یک تفاوت؛ برای خطاهای 404 و 500، حتما حتما باید
حالت دیباگ پروژه فالس باشد، وگرنه درست کار نمی کند. مثلا برای 500 همچین چیزی طراحی میکنیم:

```
{% extends 'shared/_layout.html' %}

{% block title %}
    خطا
{% endblock %}

{% block content %}
    <div class="container">
        <div class="col-lg-12">
            <h1>یک خطای سروری رخ داده است</h1>
        </div>
    </div>
{% endblock %}
```

حالا در هر فایل ویویی که خواسته باشیم میتونیم ارور را به این شکل برگردانیم:

`raise ValueError("Value Error Occurred")`

حالا اگر حالت دیباگ ترو باشد، بصورت قبل صفحه ی خطا را به برنامه نویس نشان میدهد ولی اگر دیباگ را فالس کنیم، باید حتما
الودهاستست رو هم پر کنیم:

```
DEBUG = False
ALLOWED_HOSTS = ["localhost", "127.0.0.1"]
```

والان اگر اجرا بگیریم و وارد ویویی شویم که خطای ولیواررور ریز کرده، میتونیم فایل اچتی ام الی که طراحی کرده ایم رو مشاهده
کنیم، ولی اگر هندلر این خطای 500 را مشاهده کنیم، دیگر کانتکسی ندارد، یعنی چیزی مثل متن خطا یا خطای واقعی رو اصلا به سمت
کاربر برنمیگرداند، منطقی هست، چون کاربر نباید دیتایی و مشکلی که پیش از خطا پیش اومده مشاهده کند. و در این مورد، برنامه
نویس با سیستم لاگی که وجود دارد باید خطا را پیدا کرده و آن را رفع کند.
